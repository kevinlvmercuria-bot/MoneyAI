# PostgreSQL 与企业微信维护指南

## 运行与切换

新旧版运行时均使用 PostgreSQL。SQL Server 驱动仅供一次性搬迁工具使用；SQLite 仅作为旧演示资料的只读导入来源。

全新演示库：准备 Node.js 22.13+、PostgreSQL 数据库和 `.env`，填写 `DATABASE_URL`，依次运行：

```powershell
npm ci
npm run data:prepare
npm run db:init
npm start
```

仅账号版可使用 `npm run db:init:team` 与 `npm run start:team`。结构迁移包含企微和客服表，但未配置凭据时不会调用腾讯接口。`APP_HOST` 默认 `127.0.0.1`；本次没有执行云端部署或开放公网监听。

已有 SQL Server 数据不能用全新演示初始化代替搬迁：

1. 保留当前代码、`.env`、`data/` 和可恢复的 SQL Server 备份。目标 PostgreSQL 使用独立空库，不要指向其他系统的数据库。
2. 在本机配置 `SQLSERVER_*` 来源参数和目标 `DATABASE_URL`。旧 `.env` 的 `DB_*` 来源参数仍可由搬迁工具读取，网页运行时不使用它们。
3. 运行 `npm run db:transfer:inspect`，只读核对来源表、数量和内容摘要。未知表或字段需要补齐映射，禁止忽略。
4. 先向独立试验库完整搬迁并验证，再安排正式切换。停止旧服务写入后运行：

```powershell
npm run db:transfer -- --source-stopped
```

5. 工具先在 SQL Server 实例默认备份目录创建 `COPY_ONLY, CHECKSUM` 备份，并执行 `RESTORE VERIFYONLY`；随后搬迁并逐表核对。目标有相同数据时跳过，有不同数据则整个目标事务回滚。不会删除来源记录。
6. 核对原账号登录、新旧任务、反馈、图片及重启恢复。使用 `pg_dump -Fc` 备份目标，恢复至另一独立库并复核。验收后才开放写入。

工具保留主键和密码哈希，校正自增序列；连接密码不打印。SQL Server 的 `datetime2` 按原项目 UTC 约定导入，业务 `date` 保留日期字符串。JSON 内容比较忽略对象键顺序，图片及哈希按二进制比较。

切换前可恢复旧代码和连接；新库开放写入后若需回退，先停写、导出并核对新增记录，不能直接切回旧库。源码和真实备份应放在受控位置，不提交连接串、数据库转储或真实会员资料。

迁移后账号名按小写匹配并建立大小写不敏感唯一索引；会员、产品、订单、员工及平台标识保留原字面值并按大小写精确比较。应用生成和校验的 `M0001` 等编号保持不变。不要手工改变标识大小写。

## 企微好友回访

管理员可在「员工账号管理 → 企微接入设置」填写企业 ID 和客户联系应用密钥，保存后立即应用；原服务端 `WECOM_CORP_ID` 和 `WECOM_CONTACT_SECRET` 仍作为初始配置来源。数据库已保存的配置优先，密钥不回显。自建应用需具备客户联系接口权限、列入可调用应用，并覆盖负责员工；管理员需配置平台要求的可信 IP 等接入条件。

1. 老板娘进入「员工账号管理」→「企微接入设置」→「管理已有企微绑定」，读取有客户联系权限的 userid，绑定本地已开通账号的员工。
2. 选择负责员工，读取其企微客户 ID，核对客户名称和 ID 后人工关联会员；系统不按同名自动绑定。
3. 老板娘按原流程分派任务。员工在「联系任务」或「话术工作台」在话术预览下方点击「通过企业微信发送」。
4. 选择任务，采用统一内容或逐人草稿；可为所选会员分别生成规则演示话术，再手工修改。每位会员可附一张产品库内已上传的 JPEG 实拍图。
5. 点击检查并逐人预览，再提交。文字同时受 1600 字符和 4000 UTF-8 字节限制；每批最多 50 个不同任务。模拟会员、未授权或不符合现有联系规则的会员不能真实发送。
6. 员工进入企业微信确认。工作台后台定期查询结果，也可在「企微发送记录」手动刷新。

状态含义：

| 状态 | 含义 |
| --- | --- |
| 准备发送 / 正在创建 | 内容已冻结，正在准备素材或创建任务 |
| 待企微确认 | 平台已建立任务，需要员工在企微确认 |
| 结果待核实 | 请求超时或进程中断，可能已经建立任务，禁止自动重发 |
| 平台报告已发送 | 平台报告对应客户已发送，不表示客户已读 |
| 未发送 / 失败 | 资格、素材或平台明确拒绝等原因；查看逐人原因 |

相同发送人、文字和图片合并创建平台任务；不同内容分别创建。网络请求不占用业务事务。幂等编号、任务唯一约束、会员未完成任务约束及跨进程锁共同防重。未知结果仅在平台记录、内容和完整客户集合唯一匹配时恢复跟踪；无法唯一匹配时保留待核实，不提供强制重发按钮。

存在未完成企微发送时，暂不允许撤回、改派相关任务或删除负责员工。客户授权等资格改变后，后台先读取已发送事实，再请求停止尚未发送的群发任务；平台操作与本地修改存在时间差，发送记录保留实际结果。发送成功会进入实际联系冷却，员工仍需另行登记客户反馈和预约。

接口入口为 `/api/wecom`：`status`、`employees`、`customers`、`customer`、`bindings`、`bindings/employee`、`bindings/member`、`preflight`、`submit`、`records` 和 `refresh`。读取使用 GET，其余业务写入使用 POST。提交体为 `{items:[{taskId,message,imageProductId}],idempotencyKey}`。员工不能提交任意平台客户 ID。

平台接收额度受企业后台群发规则影响，以实际接口结果为准，不在应用里假设“无限发送”。官方规则已于本次通过开发者中心页面核对：

- [创建企业群发](https://developer.work.weixin.qq.com/document/path/96366)
- [群发记录及成员执行结果](https://developer.work.weixin.qq.com/document/path/96355)

## 网页微信客服

这是独立客服渠道，不能读取原企微好友聊天。配置 `WECOM_KF_SECRET`，在企业微信后台将对应客服账号设置为通过 API 管理，并配置应用可见范围。网页与企微客户端人工接待的会话状态不能混用。

配置回调所需的 `WECOM_CALLBACK_TOKEN`、43 位 `WECOM_CALLBACK_AES_KEY` 和 CorpID，回调地址为：

```text
https://你的HTTPS域名/api/wecom/kf/callback
```

GET 校验解密 echostr；POST 验签、AES 解密、核对 CorpID 后持久化通知 token。开发时可通过后台低频拉取验证，正式使用需要可达的 HTTPS 回调。回调 token 和消息游标不下发浏览器。

1. 老板娘打开「微信客服会话」，读取客服账号并生成客户咨询入口，将入口分享给会员。
2. 会员进入客服渠道发起咨询后，后台按游标同步。消息 ID 去重，游标与消息在同一事务提交，避免重启丢消息。
3. 老板娘将会话分配给已开通的员工，可人工关联会员。员工只查看当前分配给自己账号的会话。
4. 网页查看文字与图片消息，使用文字继续回复。其他消息类型显示类型提示，第一版不提供语音播放、视频、文件下载或网页图片回复。
5. 客户最近主动发消息后的 48 小时内，每轮最多回复 5 条；本地计入企微客户端同步到的回复和待核实发送，发送前再次查询平台会话状态。最终资格以平台返回为准。

客服接口返回成功显示“平台已受理”，不能显示为送达；后续失败事件会更新为失败。超时或中断保留未知状态，不自动再次调用发送接口。聊天记录只覆盖接入后已同步保存的消息，平台仅提供最近三天可拉取数据；长时间停止服务可能无法补齐更早的消息。

接口入口为 `/api/wecom/kf`：账号同步、咨询入口、会话列表、会话分配、消息列表、图片读取、同步及文字回复。网页发送体为 `{conversationId,message,idempotencyKey}`，不接受客户端指定任意客服客户标识。

- [接收消息和事件](https://developer.work.weixin.qq.com/document/path/94670)
- [发送客服消息](https://developer.work.weixin.qq.com/document/path/94677)
- [会话状态](https://developer.work.weixin.qq.com/document/path/94669)

## 验证与维护入口

在具有创建和删除独立数据库权限的 PostgreSQL 测试实例上设置 `DATABASE_URL`，执行：

```powershell
npm run check
npm run test:team
npm test
npm run test:legacy
npm run test:integrations
npm run build:share
```

测试创建随机命名的隔离库，不重置日常库；集成测试使用受控企微响应，不发送真实消息。分享版入口只说明流程，不请求真实企微接口。

维护数据库先看 `server/db.js` 与 `database/migrations.js`；发送流程看 `server/wecom-service.js`，客服看 `server/kf-service.js`，页面入口是 `public/app/wecom.js` 和 `public/app/kf.js`。修改状态或权限时保留对应集成测试。

真实接口验收仍需管理员提供受控配置、测试员工和测试会员，分别验证好友群发确认、逐人结果、客服回调和实际网页回复。不要把受控测试当作真实发送验收。


## 管理员接入与真实联调界面

「企微接入设置」包含三个入口：保存并应用配置、连接与权限检测、真实测试向导。检测会实际获取访问凭据，并读取有客户联系权限的员工和群发记录；选择测试员工后进一步检查客户读取权限。失败时显示接口错误码及相应的密钥、可见范围、接口权限或可信 IP 原因，不把“填了配置项”当作连接成功。只读检测通过也不代表实际创建和确认发送已经成功。

真实测试向导串起：检测接入 → 选择本地员工和真实会员 → 读取企微员工/客户并人工绑定 → 预览话术 → 勾选与客户约定的确认项 → 提交一次测试 → 店员企微确认 → 刷新核对结果。管理员发起测试会记录发起人和负责员工，相关发送记录对负责员工可见；不会绕过联系授权、冷却、投诉或现有任务约束。原模拟会员不能用于真实发送，缺少真实会员时可以进入 [会员导入](member-import.md)。

员工话术页只保留「通过企业微信发送」「企微发送记录」「微信客服会话」三个联系入口，位于话术预览下方。未配置时主按钮显示「尚未配置，前往接入设置」；员工点击只查看联系管理员的指引，不能填写或查看密钥。原话术页复制、图文卡片下载及带回任务按钮已删除，任务详情原有的复制入口不受影响。

设置接口为管理员专用的 `/api/wecom/admin/settings`、`check`、`wizard`、`wizard/preview` 和 `wizard/send`；读取配置只返回企业 ID、配置状态和检测结果，不返回密钥。已有绑定和历史时不支持直接切换到另一企业，避免混淆客户标识。

配置使用 AES-256-GCM 加密后保存在 PostgreSQL 的 `wecomsettings` 表。服务器使用 `WECOM_SETTINGS_KEY`（32 字节随机值的 Base64），本机未设置时首次保存会在 `%LOCALAPPDATA%/NailMate/private/wecom-settings.key` 创建仅当前 Windows 用户和 SYSTEM 可访问的密钥文件。**备份和迁移必须同时保全数据库及这份密钥**；云端或容器需使用稳定的环境密钥，不能依赖临时磁盘。解密失败时明确报错，不静默丢弃设置。高级设置可配置微信客服密钥及回调 Token / EncodingAESKey，正式回调仍须使用外网可达的 HTTPS 地址。

数据迁移使用 `npm run db:migrate` 增量建立设置、导入暂存表和发送发起人字段，不清空原有会员或凭据。维护入口为 `server/wecom-settings.js`、`server/wecom-admin-routes.js` 和 `public/app/wecom-admin.js`。
