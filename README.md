# NailMate AI

美甲店会员复购演示。店主在驾驶舱按经营目标选人，经人工审核后模拟触达，再按目标复盘。演示数据含 2,800 位虚拟会员，不发送营销消息。

当前版本为 v3（3.0.0），适配「私域复购版」UI。附件仅提供界面和参考图，会员、任务、文案、记录与门店图片继续通过原有 API 读写 SQL Server。

## 启动

需要 Node.js 22.13 或更新版本，以及 SQL Server 2016 或更新版本（数据库兼容级别至少 130）。推荐 Node.js 24 LTS，导入脚本使用内置 `node:sqlite` 读取来源文件。

1. 在 SQL Server 中创建专用空库 `NailMate`。初始化账号需要该库的建表和写入权限。运行账号需要对本项目各表的读写权限。
2. 在本目录执行 `npm ci`，复制 `.env.example` 为 `.env` 并填写连接参数。
3. 执行 `npm run db:init`，再执行 `npm start`。
4. 打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。也可用 `GET /api/state` 检查数据库是否已经接通。

正式启动统一使用 `npm start`，开发监听使用 `npm run dev`，两者都进入 `server/main.js`。`server/index.js` 仅兼容旧命令并转发到同一入口。前端通过该 HTTP 服务加载原生 JavaScript 模块。

```powershell
npm ci
Copy-Item .env.example .env
# 填好 .env，并先在 SQL Server 中创建 NailMate 空库
npm run db:init
npm start
```

- **SQL 登录**：使用 `DB_AUTH=sql`，填写数据库账号和密码。已知 TCP 端口时填写 `DB_PORT` 并清空 `DB_INSTANCE`。用命名实例连接时填写 `DB_INSTANCE`，由 SQL Server Browser 解析实例端口。
- **Windows 集成登录**：在 Windows 上填写 `DB_AUTH=windows`，命名实例例如 `DB_HOST=localhost` 和 `DB_INSTANCE=SQLEXPRESS01`。需要安装 SQL Server ODBC 驱动和可选依赖 `msnodesqlv8`。若驱动加载失败，检查 `npm ls msnodesqlv8` 和 ODBC 安装情况。
- 使用本地开发实例的自签名证书时，可针对该连接设置 `DB_TRUST_SERVER_CERTIFICATE=true`。`.env` 只保存在本地。
- `db:init` 可重复运行，基础演示会员仅在空库时生成，来源数据按文件哈希导入。「重置演示」会清空任务、关怀记录、跟进计划和操作日志，恢复基础会员资格并重建初始任务。服务默认只监听本机回环地址，接口没有用户登录机制。

## 目录与分工

| 位置 | 接手内容 |
| --- | --- |
| `public/index.html`、`public/workspace.js` | 页面骨架与唯一前端入口；初始化、导航、事件和异步协调 |
| `public/pages/` | 七个页面的渲染与对应详情展示 |
| `public/api.js`、`public/state.js`、`public/components.js` | HTTP 请求、单一共享状态、公共展示组件 |
| `public/styles.css`、`public/styles/` | 样式入口；基础主题与业务组件适配按原有顺序加载 |
| `public/rules.js` | 前后端共用选人、匹配和话术规则，后端在写入前重新验证 |
| `server/main.js`、`server/store.js`、`server/db.js` | 后端维护路由、事务、状态流转及 SQL 连接 |
| `database/schema.sql`、`database/setup.js`、`database/demo-data.js` | 数据库同学维护表、固定演示数据和初始化 |
| [docs/api.md](docs/api.md) | 联调契约 |

页面文件分别为 `dashboard.js`、`members.js`、`care.js`、`studio.js`、`campaigns.js`、`reports.js` 和 `products.js`。修改页面布局先从对应文件阅读；操作事件和提交协调在 `workspace.js`，请求格式集中在 `api.js`。页面模块只依赖状态、公共组件、请求工具和规则，不反向依赖入口。

`rules.js` 保持后端的 CommonJS 导出，`rules-client.js` 负责浏览器兼容桥接，复用同一份规则。可变的会员、筛选、勾选和草稿状态都由 `state.js` 持有。

已核查的历史实现继续保留。`server/app.js`、`server/members.js` 和 `server/config.js` 用于旧版联调契约，`public/app.js` 仍被旧测试请求；它们不是正式服务的调用链。`database/init.js` 和 `001-schema.sql` 是旧 `wg_member` 初始化流程，正式命令使用 `database/setup.js`。旧测试通过 `npm run test:legacy` 单独运行。

## 联调顺序

1. 初始化 SQL Server，检查 `GET /api/state` 返回 2,800 位会员和一条初始待审核任务。
2. 打开驾驶舱选择「余额提醒」，勾选一位候选并入队。用审核中心修改话术并批准。
3. 选择「已预约，待到店」并确认，查看余额提醒复盘是否增加一条预约。
4. 刷新页面验证任务和记录仍在，再验证拒绝任务无法执行、重复提交不会重复生成或累计。

驾驶舱采用翻转会员卡，点击「摘要」查看当前目标的邀约草稿，返回正面勾选「加入名单」后批量入队。移动端通过左上角「工作空间」展开导航。页面显示的会员数量来自 API，任务、审核与模拟结果保存至 SQL Server。

翻卡后点击「沟通准备」，填写处理结果、顾客反馈、负责人和可选的跟进日期，再保存关怀记录。「护理跟进」页的「关怀记录与后续计划」展示已保存记录。跟进日期以 `2026-11-07` 为演示基准日，已沟通或未回复至少间隔 14 天。已处理会员退出本轮推荐；不再营销、暂不联系和联系冷却限制会参与任务审核与执行校验。

升级到关怀记录版本时，执行一次 `npm run db:init` 创建 `CareRecords` 表，然后重新启动服务。初始化保留现有会员、任务和日志。

## 来源数据库衔接

`data/nailmate.db` 是团队提交的 SQLite 模拟数据源。`npm run db:init` 先建表，再导入该文件；已有项目可单独运行 `npm run db:import`。完成后重新启动服务，左侧会显示「来源数据已导入 · 24 项演示产品」。

- 导入将 2,800 名会员映射到现有档案，将 24 项产品写入产品目录。新品推荐仅匹配已上架、已发布且标记为新品的美甲款式。联系冷却期依据来源的最近联系日期计算，已有未来预约继续拦截。
- 10 张来源表的原始行保存在 `SourceRecords`。会员详情按需展示最近消费、备注、联系、预约和护理档案，每种历史最多展示最近 10 条。图片状态为 `planned` 的产品尚待补充素材。
- 来源示例营销活动与任务作为来源快照保存。当前操作任务继续由应用生成并审核；导入保留现有任务、关怀记录和日志。关怀记录对会员资格的限制优先作用于导入档案。
- 首次导入前，旧会员档案保存到 `MemberProfileBackups`，以文件 SHA-256 关联导入批次。`ImportRuns` 记录已完成批次；同一文件重复导入会跳过。整个批次在事务中提交，失败时回滚。
- 「重置演示」清理当前操作记录，会员仍采用已导入的来源档案，历史来源快照和备份继续保留。


## 最小版本验收

在项目目录运行 `npm run check` 和 `npm test`。测试使用当前 `.env` 的 SQL Server 连接身份，临时创建随机命名的 `NailMate_Acceptance_...` 测试库，并在结束后清理。该身份需要创建和删除数据库的权限。

`npm test` 验证正式 SQL Server 入口，包括重复初始化、三类经营目标、未授权拦截、整批失败回滚、并发入队、审核状态、四种模拟结果、持久化和重置。旧内存版本的测试入口为 `npm run test:legacy`。

浏览器验收按下面顺序完成。现有数据库有演示记录时，先通过页面的「重置演示」确认清空任务和日志。

| 操作 | 通过标准 |
| --- | --- |
| 选择「余额提醒」，勾选一人入队 | 审核中心出现一条余额提醒任务 |
| 将话术修改为「验收预约」，批准 | 任务进入已批准分类 |
| 模拟执行选择「已预约，待到店」 | 余额提醒复盘显示触达 1、回复 1、预约 1、到店 0、消费 ¥0 |
| 刷新页面，重新打开复盘与任务详情 | 数字不变，话术仍为「验收预约」 |
| 新建一条任务后拒绝 | 拒绝任务无法执行 |
| 再次重置演示 | 只剩一条通用待审核任务，日志为空 |

当前交付采用固定虚拟会员，支持规则任务、真实模型文案生成与人工选择的模拟结果。所有使用者共享一个本地演示数据库，服务仅监听本机。账号登录、真实消息发送和外网部署属于后续迭代内容。

## AI 文案与产品配图

在本机 `.env` 配置 `AI_API_KEY`，可选配置 `AI_BASE_URL` 和 `AI_MODEL`，默认使用移动云 TokenPlan 的 Anthropic Messages 接口和 `Qwen/Qwen3.6-Flash`。执行一次 `npm run db:init` 创建文案与图片表，再重启服务。

1. 进入「会员档案」，按活跃度或风格筛选并勾选会员，再点击「打开话术工作台」。名单可跨页保留，每批最多 5 位；联系资格未通过的会员无法勾选。点击姓名可查看右侧档案和历史资料。
2. 在「话术工作台」选择模型并生成。系统逐位调用模型，每人输出一条文案、匹配依据和 1 至 2 个目录内产品。部分失败时保留已成功结果，页面显示各失败会员的原因。
3. 在「上传产品图并绑定产品」中选择产品和图片。支持 PNG、JPEG、WebP，单张最多 5 MB。图片保存在 SQL Server，上传后已有文案也能显示该产品最新绑定图。
4. 在结果卡中核对并编辑文案，顾客沟通预览同步更新；点击「保存修改」或「复制文案」，再下载对应图片。修改、原始文案、模型、产品编号和复制时间保存到数据库，页面展示最近 50 条。

产品库展示现有数据库目录，支持分类、搜索、无图筛选和分页。`public/assets/product-references/` 保留附件自带的 24 张参考图，`public/product-images.js` 保存对应产品名称与来源。只有编号和名称都匹配才使用参考图；门店上传图优先。参考图标明网络来源，未将其写入业务数据库，也不新增或改价产品。

产品匹配依据名称、风格、类型和描述，图片通过产品绑定关联；未提供图片时显示「待补图」。会员编号、到店天数、消费金额和风格等用于生成，会员姓名和负责人信息不放入模型请求。

文案与图片供店主自行发送。复制只记录为素材复制，保持原有联系冷却及复盘口径。生成期间避免重复提交，单个会员请求最多等待 90 秒；超时或无效响应会明确提示。重置演示会清空 AI 文案，已上传图片继续保留。`npm test` 使用受控模型响应验证业务异常，真实模型调用需要本地密钥。

后端调用与响应校验在 `server/ai-copy.js`，图片和文案接口在 `server/copy-routes.js`，前端入口仍为 `public/workspace.js`。

## 增强版界面入口

- 今日复购计划展示三类经营目标和候选依据，可预览 3 至 5 人，勾选后加入任务审核。
- 会员档案采用左侧名单、右侧档案布局，历史备注、消费和护理档案来自 SQL Server。
- 护理跟进按待处理、已记录关怀、以后再看分类，记录结果、负责人和后续日期。
- 话术工作台集中处理 AI 名单、模型选择、文案编辑、顾客预览和产品图绑定。
- 任务审核采用左侧任务列表、右侧草稿与依据；仍需人工批准并选择模拟情景。
- 复购结果按经营目标展示触达、回复、预约、到店与消费，支持查看每位会员结果。
- 产品库独立展示已有款式与护理产品，可上传门店图片并下载生成文案的配图。
- 护理跟进保留独立入口；手机端通过左上角「工作空间」切换七个页面。

产品与图片库可从护理页或话术工作台打开，点击产品的「绑定图片」会跳转到产品库上传入口。附件原型中的浏览器本地状态、规则假生成及虚构模拟结果没有替换真实接口；未提供接口的备注编辑、语气选择、图文卡合成及 AI 文案提交审核控件不作为已实现功能展示。

`codex-artifacts/` 仅保留本地验收材料，已加入 Git 忽略规则，发布不包含该目录。
