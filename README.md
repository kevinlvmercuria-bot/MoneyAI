# NailMate AI

美甲店会员关系经营演示，包含 2,800 位虚拟会员。以「关系经营版」UI 为主：八类经营机会 → 沟通工作台 → 人工审核 → 选择模拟结果 → 查看复购结果。真实 AI 只用于准备文案，不发送消息、不自动预约。

当前版本为 v4.0（4.0.0），关系经营版 UI 与现有功能已适配，经用户测试确认后发布。

## 启动与升级

需要 Node.js 22.13+、SQL Server 2016+（兼容级别至少 130）。

```powershell
npm ci
# 仅首次配置：复制 .env.example 为 .env；已有配置不要覆盖
# 在 SQL Server 中准备 NailMate 数据库，填写 .env
npm run db:init
npm start
```

打开终端提示的地址，默认 [http://127.0.0.1:3000](http://127.0.0.1:3000)。`npm start` 和 `npm run dev` 均启动 `server/main.js`；`server/index.js` 兼容旧命令并转发同一入口。通过 HTTP 加载原生 JavaScript 模块。

**从 v3.2 升级**：需运行一次 `npm run db:init`，再重启服务并强制刷新。迁移添加任务/文案上下文和会员备注覆盖表，调整任务与关怀索引以保留多次回访历史；不清空已有任务、文案、反馈或图片。初始化按来源文件哈希决定是否导入，来源变化时备份并更新会员来源资料，本地备注覆盖层独立保留。本机本轮已单独执行表结构升级并核对原表记录数量不变，无需再次初始化即可测试。

- SQL 登录：`DB_AUTH=sql`，填写账号、密码及端口/实例。Windows 集成登录：`DB_AUTH=windows`，安装 SQL Server ODBC 驱动和可选依赖 `msnodesqlv8`。
- `.env` 只保存在本机。服务默认监听本机回环地址。
- 固定演示基准日为 `2026-11-07`，筛选、冷却期和回访日期均按该日计算。

## 界面与演示顺序

底部浮动 Dock 切换六页；手机端使用同一导航。下拉选项支持搜索会员、键盘选择与 Escape 关闭；触屏及减少动态效果设置下不启用指针倾斜。

1. **今日复购计划**：全部机会、沉睡唤醒、到期复购、储值关怀、护理回访、新品预告、定时回访、日常问候。人数与资格来自当前数据库，重叠人数不相加；全部机会会从不同类别轮流选人并去重。本次可安排 3、4、5、8 人，便签始终横向单排，可滑动或用箭头查看。
2. **会员档案**：搜索、生命周期筛选、到店与消费资料、护理记录；店主可以添加、编辑和置顶备注。备注覆盖层保存到 SQL Server，原始导入资料不被改写。
3. **话术工作台**：选择单位会员、沟通目的、表达风格及具体产品。护理侧重佩戴体验，新品预告不宣称现货，定时回访和日常问候无需产品。
4. 选择模型并生成 AI 文案，或直接手写。修改和顾客预览同步，可保存、复制、下载图文卡片。每个会员/目的/产品只显示最近一条已保存文案，未保存文字在页面会话内保留，历史记录仍在数据库。
5. 点击「提交人工审核」保存当前编辑内容并建任务，在任务审核核对后批准；再手动选择未回复、已回复、已预约或已到店消费情景。任务详情的「前往话术工作台」会带入会员、沟通目的和可用的关联产品。
6. **复购结果**只统计已模拟执行的任务，展示触达、回复、预约、到店、消费及每种策略汇总。新增四阶段柱状图，进入可视区域后依次升起，可点击「重播动效」；手机端适配，减少动态效果设置下直接显示最终数值。柱状图沿用原统计口径，各阶段为累计进展，不相加。仅「已到店并消费」记录固定 168 元模拟消费，不代表真实转化或增量收入。
7. 在工作台「聊完，记录下一步」填写顾客反馈、负责人和可选日期。到期且符合联系资格的计划进入定时回访，不自动发送。续接回访会追加反馈，保留旧记录。

护理回访根据最近一次美甲服务订单筛选服务后第 1–7 天且同意护理跟进的顾客；不按沉睡周期筛选。新品预告面向活跃会员，匹配偏好及未来 14 天内计划上架的款式。日常问候要求活跃、多次到店且 30 天未联系。定时回访仍检查授权、投诉、预约、联系间隔，已执行同一计划或有待审核/已批准任务时不重复入队。近期模拟触达同样参与冷却计算。

## 演示重置

右上角「演示工具」提供两个明确分开的操作：

- **重置界面**：回到驾驶舱，恢复默认筛选和数量，关闭弹层并清除未保存草稿；不请求数据库写接口，已保存任务、AI 文案、备注、反馈及图片保留。
- **清空演示数据**：折叠在高级操作中，点击后再次确认。清空任务、AI 文案、反馈与日志，恢复初始待审核任务；图片和会员备注保留。生成进行中不能重置数据。

展位反复走界面时优先使用「重置界面」；需要从零重演整个模拟任务闭环时才清空演示数据。

## AI 与产品图

在 `.env` 配置 `AI_API_KEY`，可配置 `AI_BASE_URL` 和 `AI_MODEL`。沿用主办方 TokenPlan 的 Messages 接口，多模型列表从后端读取。没有显式默认模型配置时优先智谱 GLM-5.2，已有 `AI_MODEL` 优先生效。保留 v3.2 的 900-token 输出预算和 60 秒模型请求超时。

工作台默认按会员性格匹配沟通语气：可爱风、温柔风、直爽风、优雅风。店主可以为本次沟通临时调整，切换会员后恢复自动匹配；暂无有效标签时使用自然亲切的语气。临时选择优先于会员标签，不修改会员资料；已有文案需要重新生成才应用新语气。草稿和审核任务保留生成时的语气、选择方式和性格快照。旧接口的自然亲切、简洁直接、温柔关怀、专业推荐选项继续兼容。

`data/nailmate.db` 中的 2,800 位会员已有性格字段，性格是模拟资料中的规则推断。每人新增一条「沟通习惯」备注，包含性格和表达建议；原有备注与 `latest_note` 保留。工作台左侧同时显示性格与来源，性格和内部备注不应出现在给顾客的文案中。整理命令可重复执行，不会重复追加；已存在的性格备注不一致时停止并回滚，不静默覆盖。

```powershell
# 更新尚未整理的模拟来源文件，然后导入当前配置的本地演示库。
npm run db:personality-notes
npm run db:import
```

固定语气要求和沟通目的会传入模型，选中产品会限制到真实目录项；模型响应校验后才保存。问候/定时回访的产品数组为空，预告款式明确标记计划上架，不允许当作现货。

`public/assets/relationship-products/` 是用户提供的 UI 内嵌图片，未另行调用图片生成接口。AI 甲片示意图标注「款式参考」，网络参考图保留来源；门店上传图优先。产品库可分类、搜索、按无图筛选与分页，上传 PNG/JPEG/WebP（单张最多 5 MB）。图片存数据库；图文卡片导出只包含顾客文案和所选产品，不包含会员编号、内部备注或经营分值。

## 维护入口

| 位置 | 职责 |
| --- | --- |
| `public/index.html`、`workspace.js` | 画面骨架、初始化、导航与事件协调 |
| `public/pages/` | 六页渲染，`care.js` 提供折叠反馈与历史组件 |
| `public/state.js`、`api.js`、`components.js` | 单一共享状态、请求工具、公共展示 |
| `public/communication.js`、`communication-client.js` | 性格到沟通语气的共享规则与浏览器桥接 |
| `public/effects.js` | 原 UI 的玻璃质感、Dock、横向便签和可访问下拉交互 |
| `public/download-card.js`、`product-images.js` | 图文导出及附件图片映射 |
| `public/rules.js`、`rules-client.js` | 前后端共用规则与浏览器兼容桥接 |
| `public/styles/base.css`、`workspace.css` | 附件主视觉与 API 组件适配 |
| `server/main.js`、`store.js`、`db.js` | 路由、事务、SQL 连接和持久化 |
| `server/ai-copy.js`、`copy-context.js`、`copy-routes.js` | 模型调用、沟通上下文验证、文案和图片接口 |
| `server/relationship-routes.js` | 会员备注、手写草稿、文案提交审核 |
| `database/schema.sql`、`setup.js`、`import-source.js` | 可重复建表迁移、演示初始化、SQLite 来源导入 |
| `database/personality-notes.js` | 为已有模拟性格追加沟通备注，保留旧记录并支持重复执行 |
| [docs/api.md](docs/api.md) | 联调字段、状态和示例 |

旧 `server/app.js`、`members.js`、`config.js` 与 `public/app.js` 仍用于历史兼容测试。`database/init.js` 和 `001-schema.sql` 是旧 `wg_member` 流程；正式启动和初始化不走它们。

## 验证

```powershell
npm run check
npm test
npm run test:legacy
```

正式测试分别创建随机独立 SQL Server 库并清理，需要创建/删除测试库权限，不重置日常演示库。原有闭环与关系经营回归覆盖迁移保留、订单回访、预告资格、无产品问候、手写与 AI 文案审核、到期计划防重复、备注持久化和冷却期。

页面联调优先用受控模型响应，不重复消耗真实模型额度。所有人共用本地演示数据库；真实客户消息发送、登录及外网部署不在当前演示范围。`codex-artifacts/` 仅保存本地验收材料，不参与发布。

当前版本仍为本地演示版本。Render 与 Azure SQL 的部署适配、公开访问保护及 AI 调用额度控制尚未实施；上传仓库不代表完成云端上线。任务进入工作台后的原任务回写、触达后反馈记录与冷却规则分离、跨周期经营和进展补录属于后续业务优化，本次保留现有行为。
